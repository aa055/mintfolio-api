# mintfolio-api

Backend for **Mintfolio** — a portfolio management platform for physical precious metals.

This service is the single source of truth for all portfolio data. The frontend in [`mintfolio-web`](https://github.com/aa055/mintfolio-web) authenticates via Supabase Auth, then sends every read/write through this API. The frontend never touches Supabase tables directly.

## Stack

| Layer | Choice |
|---|---|
| Framework | FastAPI 0.115 |
| Language | Python 3.11+ |
| ORM | SQLAlchemy 2.0 (async) |
| Migrations | Alembic |
| Validation | Pydantic v2 |
| Database | Supabase Postgres |
| Auth | Verify Supabase JWTs (ES256/RS256 via JWKS; HS256 legacy) |
| HTTP client | httpx |
| Storage | Supabase Storage (signed URLs) |
| Pricing | GoldAPI.io (daily, cached) + metals.dev (5-year backfill) |
| Hosting | Not deployed yet; daily job on GitHub Actions (see project docs) |

## Getting started

### 1. Create and activate a virtual environment

```bash
# Windows (PowerShell)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# macOS / Linux
python -m venv .venv
source .venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements-dev.txt
```

### 3. Configure environment

```bash
cp .env.example .env
# Fill in DATABASE_URL, SUPABASE_*, GOLDAPI_KEY
```

### 4. Run migrations

```bash
alembic upgrade head
```

### 5. Run the dev server

```bash
uvicorn app.main:app --reload --port 8000
```

API docs: <http://localhost:8000/docs>
Health: <http://localhost:8000/health>

## Project layout

```
app/
  main.py              FastAPI app factory + middleware
  config.py            Pydantic settings (reads .env)
  db.py                Async SQLAlchemy engine + session dependency
  deps.py              Auth dependency (verifies Supabase JWT)
  models/              SQLAlchemy ORM models
    base.py            Declarative base + UUID/Timestamp mixins
  schemas/             Pydantic request/response models (the API contract)
  routers/             FastAPI route modules: auth, purchases, files, sales,
                       portfolios, transactions, prices, health
  services/            Business logic: valuation, performance, price history,
                       storage, JWT verification, GoldAPI client
  jobs/                fetch_prices (daily GoldAPI) + backfill_prices (one-time metals.dev history)
alembic/
  env.py               Reads DB URL from app.config
  versions/            Migration files (autogenerated)
tests/
  test_*.py            Health + valuation / price-history / performance maths
```

## Common commands

```bash
# Create a new migration after editing models
alembic revision --autogenerate -m "describe the change"

# Apply pending migrations
alembic upgrade head

# Roll back one revision
alembic downgrade -1

# Fetch today's GoldAPI prices into price_history (skips if already fetched today)
python -m app.jobs.fetch_prices          # add --force to replace today's snapshot

# Backfill daily price history from metals.dev (needs METALS_DEV_KEY)
python -m app.jobs.backfill_prices --dry-run   # shows how many API calls it needs
python -m app.jobs.backfill_prices             # 5 years ~ 61 calls; re-runs only fetch missing days

# Run tests
pytest

# Lint + format
ruff check .
ruff format .

# Type-check
mypy app
```

## Price data

`price_history` holds one row per metal, purity, currency, source and day.

| Source | Written by | Covers |
|---|---|---|
| `goldapi` | `app.jobs.fetch_prices`, daily | all karats; current valuation reads the latest row |
| `metalsdev` | `app.jobs.backfill_prices`, once | pure rates (24K / 999) back ~5 years |
| `manual` | `PUT /prices/manual` | a user's own rates |

`GET /prices/history` returns one pure rate per day, using GoldAPI where both sources exist and carrying the last rate over missing days. History only exists for USD-pegged currencies (USD, AED, SAR); others need historical FX (Phase 2).

### Daily job on GitHub Actions

`.github/workflows/daily-prices.yml` runs `fetch_prices` Monday–Friday at 16:37 UTC (20:37 Dubai). GitHub often starts scheduled runs hours late, so this leaves room for the run to finish on the same UTC day. It can also be started by hand from the Actions tab, with an optional "force" re-fetch. It also keeps the free Supabase project from pausing for inactivity.

Set these repository secrets (Settings → Secrets and variables → Actions):

| Secret | Value |
|---|---|
| `DATABASE_URL` | the async **Session pooler** URL from `.env` (GitHub runners need IPv4) |
| `GOLDAPI_KEY` | your GoldAPI.io key |

GitHub disables scheduled workflows in a public repository after 60 days without commits. Re-enable it from the Actions tab if that happens.
